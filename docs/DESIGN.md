## 1. 项目概述

### 1.1 一句话介绍
玩家选择一名职业，从一副弱小的初始牌组出发，沿着随机生成的分岔路线深入三层地下城，在回合制卡牌战斗中击败敌人，用战利品不断改造自己的牌组与遗物组合，最终挑战深渊之心。

### 1.2 设计目标
| 目标 | 说明 |
| --- | --- |
| 单手可玩 | 所有操作在屏幕下 2/3 区域完成，拇指可达；无需横屏 |
| 碎片时间 | 单场战斗 1–3 分钟，单局 35–50 分钟；任意时刻退出可续玩 |
| 构筑深度 | 每职业 2–3 条明确流派 + 中立牌/遗物带来的变体组合 |
| 即开即玩 | 网页打开 3 秒内可进入主菜单；支持 PWA 添加到桌面、离线游玩 |
| 原创内容 | 所有职业、卡牌、敌人、美术均为原创，不复刻任何现有作品的角色、命名与美术 |

### 1.3 目标用户
- 喜欢策略、构筑类游戏的手机玩家（18–35 岁）
- 通勤 / 午休等碎片时间游玩
- 偏好无需下载、无强制联网的轻量体验

### 1.4 世界观（简述）
古王国的地底封印着"深渊之心"。每隔百年，封印松动，地下城会重新排列它的走廊与房间。立下誓约的骑士、行走暗影的刺客、驾驭元素的星辉术士，各自为了不同理由踏入这座会"改变形状"的地下城。——随机地图在世界观上得到解释：**地下城每一次进入都会重组**。

## 3. 战斗系统

### 3.1 基础规则
| 项 | 数值 |
| --- | --- |
| 每回合能量 | 3（遗物可改变） |
| 每回合抽牌 | 5 |
| 手牌上限 | 10（超出的抽牌直接进入弃牌堆） |
| 格挡 | 回合开始时清零（除非有特殊效果） |
| 牌堆 | 抽牌堆 / 手牌 / 弃牌堆 / 消耗堆 四区 |
| 洗牌 | 抽牌堆为空时，将弃牌堆洗入抽牌堆 |

### 3.2 回合流程
```
战斗开始
  └─ 触发「战斗开始」钩子（遗物、能力）
  └─ 固有牌置入手牌，抽满至 5 张
玩家回合
  1. 回合开始：格挡清零 → 能量重置 → 触发「回合开始」钩子 → 抽牌
  2. 行动阶段：打出卡牌 / 使用药水（无次数限制，受能量约束）
  3. 点击「结束回合」
  4. 回合结束：触发「回合结束」钩子 → 结算手牌中诅咒/状态 → 非保留牌进入弃牌堆
敌人回合
  1. 敌人格挡清零
  2. 结算敌人身上的状态（中毒、灼烧等）
  3. 按从左到右顺序执行意图
  4. 生成下一回合意图（玩家可见）
回到玩家回合……
任一方全部阵亡 → 战斗结束
```

### 3.3 意图系统
敌人在玩家回合开始时显示**下一步行动的意图图标**，玩家据此决策。

| 意图 | 图标 | 显示 |
| --- | --- | --- |
| 攻击 | 剑 | 伤害值 × 次数（已计算力量 / 虚弱 / 易伤） |
| 防御 | 盾 | 无数字 |
| 增益 | 向上箭头 | — |
| 减益 | 骷髅水滴 | — |
| 攻击 + 其他 | 剑 + 小图标 | 伤害值 |
| 召唤 | 漩涡 | — |
| 未知 / 蓄力 | 问号 | — |
| 逃跑 | 脚印 | — |

意图选择规则：每种敌人有一个**行为模式**（固定循环 / 加权随机 / 条件触发），通常附带"同一行动不得连续出现超过 N 次"的约束，以保证可读性。

### 3.4 伤害与格挡结算公式
```
攻击伤害 = floor( (基础伤害 + 力量) × 攻击者虚弱系数 × 目标易伤系数 )
  虚弱系数 = 0.75（存在虚弱时），否则 1
  易伤系数 = 1.5（存在易伤时），否则 1
  最小为 0

获得格挡 = floor( (基础格挡 + 敏捷) × 脆弱系数 )
  脆弱系数 = 0.75（存在脆弱时），否则 1

受击：先扣格挡，剩余扣生命。
「失去生命」类效果（如血誓、中毒）无视格挡。
```

结算顺序（同一张牌）：按卡面文本从左到右依次执行；多段攻击每段独立结算格挡、荆棘与"受击时"触发效果。

### 3.5 状态效果（Buff / Debuff）
| 名称 | 类型 | 效果 | 衰减 |
| --- | --- | --- | --- |
| 力量 | 增益 | 攻击伤害 +N（每段） | 不衰减 |
| 敏捷 | 增益 | 卡牌获得格挡 +N | 不衰减 |
| 荆棘 | 增益 | 被攻击时，对攻击者造成 N 点伤害 | 不衰减（"本回合"荆棘回合结束清除） |
| 再生 | 增益 | 回合结束回复 N 生命 | 每回合 -1 |
| 护符 | 增益 | 抵消下一次负面状态，层数 -1 | 消耗型 |
| 易伤 | 减益 | 受到攻击伤害 ×1.5 | 每回合 -1 |
| 虚弱 | 减益 | 造成攻击伤害 ×0.75 | 每回合 -1 |
| 脆弱 | 减益 | 获得格挡 ×0.75 | 每回合 -1 |
| 中毒 | 减益 | 回合开始失去 N 生命 | 每回合 -1 |
| 灼烧 | 减益 | 回合结束受到 N 点伤害（受格挡），随后层数减半（向下取整） | 减半 |
| 寒霜 | 减益 | 下一次攻击伤害 -N，攻击后清空；层数 ≥10 时**冻结**：跳过下个行动，清空寒霜 | 见左 |
| 感电 | 减益 | 每次受到攻击时额外受到 N 点伤害，随后层数 -1 | 触发后 -1 |
| 标记 | 减益 | 每次受到攻击时额外受到 N 点伤害（不衰减，战斗内持续） | 不衰减 |
| 冻结 | 控制 | 跳过下一个行动；Boss 免疫，改为获得 2 层虚弱 | 一次性 |

### 3.6 卡牌关键词
| 关键词 | 说明 |
| --- | --- |
| 消耗 | 打出后移入消耗堆，本场战斗不再出现 |
| 虚无 | 回合结束时若仍在手牌，则消耗 |
| 固有 | 战斗开始时必定在初始手牌中 |
| 保留 | 回合结束时不弃置 |
| X | 消耗全部剩余能量，X = 消耗量 |
| 不可打出 | 无法主动打出 |
| 衍生 | 由其他效果生成，不会出现在奖励与商店中 |
| 共鸣（术士） | 若上一张打出的牌与本牌元素相同，触发额外效果 |
| 连击（夜行者） | 本回合已打出的牌数（含本张之前） |
| 誓约（骑士） | 骑士专属资源，战斗内保留，上限 10 |

## 4. 职业设计

### 4.1 职业总览
| 职业 | 生命 | 初始遗物 | 核心资源 | 定位 | 难度 |
| --- | --- | --- | --- | --- | --- |
| 铁誓骑士 | 80 | 誓约徽章 | 誓约 / 荆棘 | 高防御、厚积薄发 | ★☆☆ 入门 |
| 夜行者 | 70 | 影之斗篷 | 连击 / 毒 / 飞刀 | 多卡联动、高节奏 | ★★☆ 进阶 |
| 星辉术士 | 65 | 元素棱晶 | 元素共鸣 | 打出顺序规划、状态叠加 | ★★★ 高阶 |

> 解锁：铁誓骑士默认解锁；用任意职业到达第二层解锁夜行者；击败第一层 Boss 两次解锁星辉术士。

### 4.2 铁誓骑士
- **概念**：以盾为誓的守护者。通过防御积累「誓约」，在关键回合一次性释放审判。
- **核心机制 · 誓约**：战斗内资源，不随回合清空，上限 10（可被能力提升）。来源为部分防御牌；消耗方为「审判」系攻击牌，或作为条件增幅卡牌。
- **流派**
  1. **誓约爆发**：立誓 / 誓约祈祷 / 不屈 → 审判 / 终焉裁决 / 王者之剑
  2. **荆棘反击**：荆棘甲 / 坚守 / 圣光反冲，靠敌人攻击自伤
  3. **铁壁格挡**：守护姿态 / 不灭壁垒 / 盾击，以格挡转化伤害
- **初始牌组（10 张）**：斩击 ×5、举盾 ×4、立誓 ×1
- **初始遗物 · 誓约徽章**：战斗结束时回复 6 生命。

### 4.3 夜行者
- **概念**：在阴影中游走的刺客，以大量低费牌制造连击，用毒与飞刀蚕食敌人。
- **核心机制 · 连击**：本回合已打出的牌数，许多卡牌在连击达到阈值时追加效果。
- **流派**
  1. **剧毒**：淬毒 / 毒雾 / 毒性催化 / 剧毒之心 / 毒爆
  2. **飞刀**：抛掷飞刀 / 暗器大师 / 无影，大量 0 费衍生牌
  3. **连击爆发**：致命节奏 / 刀刃风暴 / 千刃 / 割喉
- **初始牌组（10 张）**：刺击 ×5、闪避 ×4、暗影步 ×1
- **初始遗物 · 影之斗篷**：每场战斗第一回合额外抽 2 张牌。

### 4.4 星辉术士
- **概念**：操纵火、霜、雷三种元素的学者。牌的**打出顺序**决定威力。
- **核心机制 · 元素共鸣**：带元素标签（火 / 霜 / 雷）的牌，若与上一张打出的牌元素相同，触发【共鸣】效果。无元素牌会**打断**共鸣链。
  - 火：伤害 + 灼烧（持续伤害）
  - 霜：格挡 + 寒霜（削弱攻击 / 冻结）
  - 雷：多目标 + 感电（放大多段攻击）
- **流派**
  1. **烈焰**：火球术 / 烈焰之触 / 陨石 / 超新星
  2. **冰封**：霜冻射线 / 冰锥 / 绝对零度 / 冰封之心 / 永冬
  3. **雷霆**：电弧 / 链状闪电 / 电容 / 天雷引 / 雷霆万钧
  4. **全元素**：三相棱镜 / 元素宗师 / 元素风暴（高阶混搭）
- **初始牌组（10 张）**：火花 ×5、冰盾 ×4、元素调和 ×1
- **初始遗物 · 元素棱晶**：每场战斗第一张元素牌必定触发共鸣。

### 5.2 卡牌类型
- **攻击**：造成伤害，通常需要选择目标

### 6.2 设计原则
1. **一个敌人一个教学点**：每种敌人至少考验一种玩家能力（防御、爆发、AOE、净化、节奏）。
2. **意图可读**：行为模式简单、可预测；复杂度主要来自敌人组合。
3. **数值随层递增**：普通敌人生命 第一层 12–50，第二层 40–85，第三层 60–110。
4. 生命值给出范围，生成时在范围内随机（进阶难度 +10%）。
5. 每层前 3 场战斗只从「弱遭遇池」抽取，之后使用「强遭遇池」。

## 7. 地图与路线生成

### 7.1 结构
- 每层 15 层楼 + Boss 层，网格 7 列 × 15 行
- 从第 1 行随机选取起点，生成 6 条路径逐行向上连接（每步只能连接相邻 3 列中的一个），路径可以交汇但**不允许交叉**
- 所有路径在第 15 行汇聚到 Boss

### 7.2 节点类型与权重
| 节点 | 图标 | 基础权重 | 规则 |
| --- | --- | --- | --- |
| 普通战斗 | ⚔ | 45% | 第 1 行全部为普通战斗 |
| 事件 | ? | 22% | 内部 10% 概率变为战斗、5% 变为商店（未知房间） |
| 精英 | 😈 | 8% | 第 6 行之前不出现 |
| 休息 | 🔥 | 12% | 第 6 行之前不出现；第 14 行必定为休息 |
| 商店 | 💰 | 5% | 第 3 行之前不出现 |
| 宝箱 | 📦 | 固定 | 第 9 行全部为宝箱 |
| Boss | 👑 | 固定 | 第 16 行 |

### 7.3 约束（生成后校验，不满足则重抽）
1. 精英、休息、商店不能连续出现在同一路径上
2. 同一节点的不同出边指向的节点类型不同（保证分岔有意义）
3. 每层至少 2 个精英、至少 3 个休息点、至少 1 个商店
4. 进阶 ≥1 时精英权重 ×1.6

### 7.4 种子
整局使用一个 **种子字符串**（可分享），地图、遭遇、奖励、事件使用独立的子 RNG 流（见 13.5），保证同种子同结果，同时避免"重开战斗刷奖励"。

| 奖励 | 卡片式列表，逐项领取；卡牌三选一横排放大展示 |
| 商店 | 上半卡牌（2 行横滑），下半遗物 / 药水 / 删卡 |

| 设置 | 音量、动画速度（1x/2x/3x）、震动、结束回合提示、语言、数据导出 |

### 11.6 反馈与爽感
- 受击：敌人抖动 + 白闪 + 数字飘字；暴击级伤害（≥20）屏幕轻震
- 打出卡牌：卡牌飞向目标的轨迹动画 ≤250ms
- 手机震动（`navigator.vibrate`）：受到伤害 30ms，击杀 60ms（可关闭）
- 动画速度可加速，所有动画可被下一次输入打断（逻辑先行、表现追赶）

## 13. 技术架构

### 13.1 技术选型
| 层 | 选型 | 理由 |
| --- | --- | --- |
| 语言 | TypeScript（strict） | 卡牌/效果数据结构复杂，类型安全收益高 |
| 构建 | Vite | 快速 HMR，产物小，PWA 插件成熟 |
| UI 框架 | Preact + Signals | 体积 ~4KB，组件化管理大量界面；Signals 精细更新避免整树重渲染 |
| 动画 | CSS Transform + Web Animations API | GPU 合成，卡牌动画流畅 |
| 特效 | Canvas 2D 粒子层（叠加在 DOM 之上） | 轻量，不引入游戏引擎 |
| 状态逻辑 | 纯 TS 引擎（无 DOM 依赖） | 可单测、可无头模拟、可回放 |
| 存储 | IndexedDB（idb-keyval）+ localStorage 兜底 | 存档、设置、统计 |
| 离线 | vite-plugin-pwa（Workbox） | 添加到主屏幕、离线游玩 |
| 测试 | Vitest + Playwright（移动视口） | 单元 / 模拟 / E2E |
| 部署 | 静态托管（GitHub Pages / Cloudflare Pages） | 零后端 |

> 不选 Phaser / Pixi 等引擎的原因：卡牌游戏以 UI 为主，DOM 在文字排版、可访问性、响应式适配上更有优势；特效由轻量 Canvas 层补足。若后期特效需求剧增，可将战斗场景层替换为 PixiJS，引擎层不受影响。

### 13.2 分层架构
```
┌─────────────────────────────────────────────┐
│  表现层 (src/ui)  Preact 组件 / 动画 / 输入   │
│        ▲ 订阅事件流            │ 发送指令     │
│        │                       ▼             │
│  适配层 (src/app) GameController             │
│        事件 → 动画队列；指令校验；存档触发    │
│        ▲                       │             │
│        │ GameEvent[]           ▼ Command     │
│  引擎层 (src/engine) 纯函数式规则引擎        │
│     RunState / CombatState / ActionQueue     │
│     Hooks（遗物/能力/状态）/ RNG             │
│        ▲                                     │
│  数据层 (src/data) 卡牌/敌人/遗物/事件定义    │
└─────────────────────────────────────────────┘
```
**关键原则：引擎先算完，表现层只负责"播放"引擎产生的事件序列。** 这样：
- 动画加速/跳过不影响逻辑
- 任何时刻存档都是一致的
- 可以无 UI 跑上万场模拟进行平衡测试

### 13.3 动作队列（Action Queue）
所有效果都被拆解为原子 Action，压入队列依次执行：
```
打出「重劈」
 → PayEnergy(2)
 → MoveCard(hand → resolving)
 → Damage(source=player, target=E1, amount=14)
      ├─ 触发 onBeforeDamage 钩子（力量/虚弱/易伤修正）
      ├─ 扣格挡、扣生命 → 产出事件 DamageDealt
      └─ 触发 onAfterDamage（荆棘、感电、遗物…）→ 新 Action 插入队首
 → ApplyStatus(E1, Vulnerable, 1)
 → MoveCard(resolving → discard)
 → 触发 onCardPlayed 钩子
 → CheckCombatEnd
```
- 新产生的触发型 Action **插入队首**（深度优先），保证"效果的效果"立即结算
- 每个 Action 执行后产出 `GameEvent`，供表现层播放
- 死亡检测在每个 Damage 后进行；敌人死亡时清除其待执行 Action

### 13.4 钩子系统
遗物、能力、状态、诅咒统一实现 `Hookable` 接口，引擎在固定时机广播：

| 钩子 | 时机 |
| --- | --- |
| onRunStart / onPickup | 局开始 / 获得时 |
| onCombatStart / onCombatEnd | 战斗开始 / 结束 |
| onTurnStart / onTurnEnd | 回合开始 / 结束（分玩家与敌人） |
| onCardDrawn / onCardPlayed / onCardExhausted | 卡牌事件 |
| modifyDamageDealt / modifyDamageTaken / modifyBlock | 数值修正（纯函数，按优先级排序） |
| onDamageTaken / onAttacked / onHpLost | 受伤后 |
| onStatusApplied | 获得状态时（护符在此拦截） |
| onShuffle / onPotionUsed / onGoldGained / onRestSite / onEnterNode | 其他 |

修正类钩子带 `priority`，固定顺序：加法修正（力量）→ 乘法修正（虚弱、易伤）→ 最终修正（上限/下限、神圣护佑）。

### 13.5 随机数
- 算法：`sfc32`（种子由字符串哈希得到），状态可序列化
- **独立 RNG 流**：`map`、`encounter`、`cardReward`、`relic`、`potion`、`event`、`shop`、`combat`（洗牌、随机目标）、`ai`（敌人意图）
- 进入每场战斗时，`combat` 与 `ai` 流由 `runSeed + floor` 重新派生，确保读档重进战斗结果一致，杜绝 SL 刷结果

### 13.6 卡牌效果数据化（Effect DSL）
> **v0.1 实现说明**：当前代码采用「数值表 `v` + `play(ctx)` 脚本」的形式（见 `src/data/cards/*.ts`），卡面文本中的 `{d}`/`{b}` 占位符会根据力量、虚弱、易伤、敏捷等实时计算并高亮。下面的纯声明式 DSL 作为后续演进方向保留。

绝大多数卡牌只需声明式数据，少量复杂牌使用自定义脚本：
```ts
// 重劈
{
  id: 'knight_heavy_cleave', name: '重劈', cost: 2, type: 'attack',
  rarity: 'common', class: 'knight', target: 'enemy',
  effects: [
    { op: 'damage', amount: 14 },
    { op: 'applyStatus', status: 'vulnerable', amount: 1 },
  ],
  upgrade: { effects: [{ op: 'damage', amount: 18 }, { op: 'applyStatus', status: 'vulnerable', amount: 2 }] },
}

// 火球术（共鸣）
{
  id: 'mage_fireball', name: '火球术', cost: 2, type: 'attack', element: 'fire',
  effects: [
    { op: 'damage', amount: 12 },
    { op: 'applyStatus', status: 'burn', amount: 3 },
    { op: 'if', cond: { resonance: true }, then: [{ op: 'applyStatus', status: 'burn', amount: 3 }] },
  ],
}

// 审判（变量）
{
  id: 'knight_judgment', name: '审判', cost: 2, type: 'attack',
  effects: [
    { op: 'setVar', name: 'n', value: { resource: 'oath' } },
    { op: 'gainResource', resource: 'oath', amount: { mul: [{ var: 'n' }, -1] } },
    { op: 'repeat', times: { var: 'n' }, do: [{ op: 'damage', amount: 5 }] },
  ],
}
```
DSL 原语（约 30 个）：`damage / damageAll / damageRandom / block / draw / discard / exhaust / gainEnergy / applyStatus / removeStatus / addCardToHand / addCardToPile / upgradeCards / heal / loseHp / gainResource / if / repeat / setVar / choose / script` 等。
卡面描述文本由 DSL **自动生成**并支持动态数值（实时显示力量、虚弱修正后的伤害），避免文本与逻辑不一致。

### 13.7 存档
- **存档时机**：进入节点时、每次玩家指令执行完毕后、回合结束后（防止杀进程丢进度）
- **存档内容**：`RunState` 完整快照 + 各 RNG 流状态；战斗中额外保存 `CombatState`
- **格式**：JSON + 版本号 `schemaVersion`，提供迁移函数链
- **防篡改**：不做强校验（单机游戏），仅做简单校验和以检测损坏
- **导出/导入**：设置中可导出 Base64 存档字符串，便于换设备

### 13.8 性能目标
| 指标 | 目标 |
| --- | --- |
| 帧率 | 中端安卓（骁龙 7 系 / 4GB）战斗中稳定 60fps |
| 首屏 | 4G 网络下 ≤3s 可交互 |
| 内存 | ≤150MB |
| 单次指令引擎计算 | ≤5ms |

手段：只对 `transform/opacity` 做动画；手牌使用绝对定位 + transform 布局；图片图集化；路由级代码分割（战斗 / 地图 / 商店）；`visibilitychange` 时暂停动画与音频。

## 14. 数据结构定义

```ts
type ClassId = 'knight' | 'rogue' | 'mage' | 'neutral' | 'curse' | 'status';
type CardType = 'attack' | 'skill' | 'power' | 'curse' | 'status';
type Rarity = 'basic' | 'token' | 'common' | 'uncommon' | 'rare' | 'special';
type Element = 'fire' | 'frost' | 'lightning';
type TargetType = 'none' | 'enemy' | 'allEnemies' | 'randomEnemy' | 'self';
type Keyword = 'exhaust' | 'ethereal' | 'innate' | 'retain' | 'unplayable';

interface CardDef {
  id: string;
  name: string;
  class: ClassId;
  type: CardType;
  rarity: Rarity;
  cost: number | 'X' | null;   // null = 不可打出
  target: TargetType;
  element?: Element;
  keywords?: Keyword[];
  effects: Effect[];
  upgrade: Partial<Pick<CardDef, 'cost' | 'effects' | 'keywords'>>;
  art: string;
}

interface CardInstance {
  uid: string;          // 实例唯一 id
  defId: string;
  upgraded: boolean;
  costOverride?: { value: number; until: 'turn' | 'combat' | 'played' };
}

interface EnemyDef {
  id: string;
  name: string;
  tier: 'normal' | 'elite' | 'boss';
  act: 1 | 2 | 3 | 4;
  hp: [number, number];
  moves: Record<string, EnemyMove>;
  ai: EnemyAI;              // 'cycle' | 'weighted' | 自定义脚本
  passives?: HookDef[];     // 如「再生」「分裂」
}

interface EnemyMove {
  intent: 'attack' | 'defend' | 'buff' | 'debuff' | 'attackDebuff' | 'summon' | 'unknown' | 'escape';
  effects: Effect[];
}

interface RelicDef {
  id: string;
  name: string;
  rarity: 'starter' | 'common' | 'uncommon' | 'rare' | 'boss' | 'shop' | 'event';
  class?: ClassId;
  hooks: HookDef[];
  counter?: number;         // 计数类遗物（墨水瓶等）
}

interface RunState {
  schemaVersion: number;
  seed: string;
  rng: Record<RngStream, RngState>;
  classId: ClassId;
  ascension: number;
  hp: number; maxHp: number;
  gold: number;
  deck: CardInstance[];
  relics: { id: string; counter?: number }[];
  potions: (string | null)[];
  act: number; floor: number;
  map: MapGraph;
  currentNode: string | null;
  cardRarityOffset: number;  // 保底
  potionChance: number;
  removeCost: number;
  combat?: CombatState;
  stats: RunStats;
}

interface CombatState {
  turn: number;
  phase: 'playerTurn' | 'enemyTurn' | 'resolving' | 'won' | 'lost';
  energy: number; maxEnergy: number;
  player: { block: number; statuses: StatusMap; resources: { oath?: number } };
  enemies: EnemyInstance[];
  piles: { draw: CardInstance[]; hand: CardInstance[]; discard: CardInstance[]; exhaust: CardInstance[] };
  powers: { id: string; amount: number }[];
  turnCounters: { cardsPlayed: number; attacksPlayed: number; lastElement?: Element | null; elementsPlayed: Element[] };
  queue: Action[];
}

// 玩家指令（UI → 引擎）
type Command =
  | { type: 'playCard'; uid: string; target?: string }
  | { type: 'usePotion'; slot: number; target?: string }
  | { type: 'endTurn' }
  | { type: 'chooseOption'; choiceId: string; selection: string[] }
  | { type: 'selectNode'; nodeId: string }
  | { type: 'pickReward'; rewardId: string; option?: string };

// 引擎事件（引擎 → UI）
type GameEvent =
  | { type: 'cardDrawn'; uid: string }
  | { type: 'cardPlayed'; uid: string; target?: string }
  | { type: 'damage'; target: string; amount: number; blocked: number; hpLeft: number }
  | { type: 'blockGained'; target: string; amount: number }
  | { type: 'statusChanged'; target: string; status: string; amount: number }
  | { type: 'intentChanged'; enemy: string; intent: IntentView }
  | { type: 'enemyDied'; enemy: string }
  | { type: 'shuffle' }
  | { type: 'combatEnd'; result: 'won' | 'lost' };
```

### 15.1 卡牌价值基准（普通稀有度，未升级）

3. 每周出一份平衡报告，调整后回归模拟

## 18. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 小屏信息过载 | 可读性差 | 关键词点击解释、长按详情、默认隐藏次要信息；320 宽机型专项测试 |
| 卡牌交互误触 | 体验差 | 打出需越过阈值线；有目标牌必须明确落在敌人上；结束回合按钮远离手牌 |
| 效果组合爆炸导致 bug | 崩溃 / 死循环 | 原子 Action + 钩子优先级；Action 执行上限；模拟器大规模随机测试 |
| 数值失衡 | 某流派过强 | 数据驱动 + 模拟报告 + 每周平衡 |
| iOS Safari 兼容性 | 音频、100vh、手势冲突 | `dvh`、`touch-action: none`、禁用双击缩放、首次交互解锁音频 |
| 内存被系统回收 | 进度丢失 | 每个指令后写入存档；`visibilitychange` 立即保存 |
| 美术产能不足 | 延期 | 先用 SVG 符号化占位卡面并保证可玩；美术按"职业立绘 → 敌人 → 卡面"优先级排期 |
| 内容同质化 / 与现有作品雷同 | 口碑、版权 | 所有命名与机制（誓约、连击、元素共鸣）原创设计，美术原创，评审时做相似度检查 |
